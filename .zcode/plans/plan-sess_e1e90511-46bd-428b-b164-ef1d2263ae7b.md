## iter84b — Physics-Calibrated SDE Coefficients from Token Population Statistics

### Problem restatement

Iter84 failed because: (a) it used global macro signals (SOL price/vol) that don't discriminate the traded token population; (b) it tuned only 4 of 17 parameters, all in the same direction; (c) it used pre-baked constant overrides rather than genuine data-driven calibration; (d) there was no smoke-test phase to verify the coefficients cause meaningfully different engine behavior.

This plan addresses all four.

---

### Core principle: estimate SDE coefficients from what the tokens actually look like

Every free parameter in the V2 SDE system has a closed-form relationship to observable statistics in the candle data. We compute those statistics from the last ~50 completed recordings before the session start (backtest-safe: only recordings with `started_at < current_session_started_at`), then invert the SDE stationarity equations to get coefficient estimates.

### The complete calibration map (all 13 free SDE parameters we'll touch; s_0, s_1, eps_div held fixed — exchange physics, not regime-dependent)

| Coefficient | Default | Observable estimator | Formula |
|---|---|---|---|
| `sigma_mu` | 0.10 | Realized second-difference drift vol | `std(log(c[t]/c[t-2]) - log(c[t-1]/c[t-2]))` across all candles, median across recordings |
| `lambda_mu` | 0.15 | Price log-return autocorrelation lag-1 decay | `max(0.05, -log(max(ε, |ρ_1|)) / Δt)` where ρ_1 is median lag-1 autocorr |
| `kappa_mu` | 0.05 | Δdrift ~ Δflow regression slope | `cov(Δr_t, Δφ_t) / var(Δφ_t)`, clipped to [0.01, 0.20] |
| `sigma_phi` | 0.15 | Std of normalized buy-sell imbalance | `std((buy_vol - sell_vol)/(vol + 1))` across candles, median across recordings |
| `alpha` | 0.20 | Order-flow autocorrelation half-life | `log(2) / t_half`, where t_half from lag-1 autocorr of φ series |
| `beta` | 1.00 | Sensitivity of φ to volume imbalance | `sigma_phi_obs / (median_candle_vol + ε)`, clipped to [0.2, 5.0] |
| `eta` | 0.10 | Log-variance autocorrelation decay rate | `max(0.05, -log(|ρ_1(log r²)|))` |
| `sigma_h` | 0.20 | Std of Δlog(realized_var) | `std(Δlog(r²))` across candles, median across recordings, clipped to [0.05, 0.80] |
| `theta` | 0.10 | Pool-sol autocorrelation decay rate | `-log(max(ε, |ρ_1(pool_sol)|))`, clipped to [0.02, 0.50] |
| `sigma_ell` | 0.10 | Std of Δlog(pool_sol) per candle | `std(Δlog(pool_sol))`, clipped to [0.01, 0.50] |
| `zeta` | 0.30 | Mean Δlog(pool_sol) on volume-spike candles | median `|Δlog(pool_sol)|` where vol > 3×median_vol, clipped to [0.05, 1.0] |
| `lambda_0` | 1/14400 | Inverse typical recording duration | `1 / median_recording_duration_seconds` from recent recordings |
| `tau_max` | 30 | Horizon tied to price autocorrelation timescale | `min(60, max(10, 1 / lambda_mu))`, rounded to nearest 5 |

**What is NOT changed:** `kappa_J` (jump rate — heuristic override anyway), `lambda_1` (unused in kernel), `confidence_high` (pure gate, separate mechanism), `n_particles`, `n_grid`, `warmup_bars`, all EVR/HF/delay/rate-split knobs. The 5 `_ALWAYS_EXPLICIT` knobs are always included.

### Architecture

#### New file: `backend/session_calibrator.py` (replace entirely)

```
calibrate_from_population(db_path, before_unix, n_recs=50) → dict
  └─ SQL: SELECT last 50 completed recordings with started_at < before_unix
  └─ SQL: JOIN candles for those recordings (open, close, volume, buy_volume, sell_volume, pool_sol)
  └─ Compute per-recording statistics (all formulas above)
  └─ Take median across recordings (robust to outliers)
  └─ Map through formula table → coefficient dict
  └─ Merge with _ALWAYS_EXPLICIT
  └─ Return dict (falls back to _ALWAYS_EXPLICIT on any error)

calibrate_from_history(started_at_unix) → dict   [backtest sync path]
  └─ opens price_data.db, calls calibrate_from_population(db, started_at_unix)

calibrate_async(db_path) → dict   [live async path]
  └─ runs calibrate_from_population in executor (it's a DB query, no network)
  └─ 5-minute in-process cache
```

The `sol_price_history.json` becomes irrelevant — we don't use macro signals at all. The regime classifier (`_select_regime`, `_REGIME_A`, `_REGIME_B`, etc.) is removed.

#### Modified files
- `backend/main.py`: swap `calibrate_async()` call to pass `db_path` arg
- `backend/backtester.py`: `calibrate_from_history(started_at)` already wired — stays the same call signature, but now reads from DB instead of JSON cache
- `backend/analysis/test_session_calibrator.py`: replace all 29 tests with new tests against the population-estimator logic

### Smoke-test protocol (required BEFORE running any full burn)

A new script `backend/analysis/iter84b_smoke.py`:

1. Sample 30 random recordings from the post-Aug-20 train set
2. For each recording, run ForwardTester twice: once with DEFAULT_CONFIG, once with calibrated coefficients
3. Collect per-tick internal state: `mu_post` (posterior drift), `sigma_t` (log-vol), `phi_post` (order flow), particle entropy, signal_strength
4. Compare distributions: t-test on means, KS test on CDFs
5. Also compare outcome metrics: trades, WR, PnL (paired per-recording)
6. **Gate**: pass if internal state distributions differ (KS p < 0.05 on at least 2 of 5 state vars) AND paired PnL CI does not clearly go negative (CI lower > −0.005 SOL mean per recording)

Only if smoke passes → proceed to full 510-recording train burn.

**Convergence loop**: if the initial coefficient estimates produce no material state difference (KS p > 0.05 on all vars), investigate which formulas are degenerate (e.g., log-return autocorr near zero → lambda_mu estimate collapses to default) and adjust the clipping bounds. The goal is convergence to a parameter set that genuinely changes engine behavior.

### Burn plan (same preregistration structure as iter84)

**Cells** (all with `use_session_calibration: False` to use explicit params):
- `iter84b_base_post`: DEFAULT_CONFIG on post-Aug-20 train (510 recs) — reuse iter84's `iter84_base_post` batch
- `iter84b_cal_post`: Calibrated coefficients on post-Aug-20 train (510 recs)
- `iter84b_base_pre`: DEFAULT_CONFIG on pre-Aug-20 train (687 recs) — reuse `iter84_base_pre` batch
- `iter84b_cal_pre`: Calibrated coefficients on pre-Aug-20 train (687 recs) [for H2 stability]

**Smoke test first** — run smoke on 30-sample before committing to the full burn.

**Acceptance gates (same protocol):**
- H1: Wilcoxon one-sided p < 0.05, bootstrap CI low > 0, breadth ≥ 50% on post-era train
- H2: two-sided p > 0.05 OR ΔPnL > −0.02 SOL on pre-era (calibration must not harm the old regime)
- H3: post-era expectancy/trade ≥ 0.003 SOL OR trades/rec median ≥ 1.5 (at least one symptom metric improves ≥15%)

### Implementation steps

1. **Write `calibrate_from_population()`** with all 13 formula estimators + robust median-across-recordings aggregation + clipping bounds + fallback
2. **Update public API** — `calibrate_from_history(started_at)` and `calibrate_async(db_path)` keep same signatures, new internals
3. **Remove** regime classifier, price history cache dependency, `_REGIME_A/B` dicts
4. **Write new test suite** — synthetic candle data covering edge cases (zero pool_sol rows, flat price, zero volume candles), verify formulas against known closed-form results, test fallback
5. **Write `iter84b_smoke.py`** — the ForwardTester comparison loop with KS tests and per-tick state capture
6. **Run smoke, check convergence** — if internal state genuinely different: proceed; otherwise, tighten/adjust clipping
7. **Pre-register cells + run burns** (sequential, engine sha locked)
8. **Screen + adopt** per preregistration gates

### What this is NOT doing

- No regime classifier or threshold lookup
- No MSM/HMM machinery from previous iterations
- No global macro signals (SOL price, PumpSwap volume) as primary drivers
- No pre-baked constant override dicts
- No tuning of only a small subset of parameters
- No "pick a direction and hope" — formula-driven from the SDE mathematics
